## 二、统一的拆分模式（跨 7 阶段保持一致）

1. **barrel 主入口保留**：原文件变为 barrel re-export + 精简类（生命周期 / 状态字段 / 薄委托方法），**外部 `import` 路径不变**，零破坏。
2. **子模块取 `view: IOTOTaskView` 为首参**：抽取的方法改为模块级函数 `export function xxx(view, ...)`，跨模块调用一律走 `view.xxx()` 委托，避免循环依赖。
3. **私有字段按需公开**：被子模块读取的 `private` 字段/方法改为 `public`，getter/setter 语义保留。
4. **模块内私有辅助不下放类**：仅在同模块内调用的 helper 留作模块级非导出函数。
5. **public API 全部保留**：`main.ts`、`task-view-routing.ts`、`task-file-opening.ts` 等外部调用的方法（`applyAppearanceStyle`、`flushInlineEdits`、`canAddTask`、`getItemControlHost` 等）以薄委托形式继续挂在类上。
6. **依赖注入不变**：视图仍通过 getter/updater 回调读/写设置，绝不向子模块泄漏 plugin 单例。

## 三、关键约束与不变量

- **零行为变更**：所有逻辑逐字搬移，仅做 `this`→`view` 的机械改写。
- **TypeScript 严格模式 + Tab 缩进**：全程遵守。
- **i18n 不破坏**：所有用户可见字符串仍经 `t()`，未硬编码。
- **AGENTS.md 同步更新**：每个阶段的源码结构章节都已反映新模块。

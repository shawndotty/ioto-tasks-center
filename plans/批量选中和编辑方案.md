# ITC批量选中和编辑方案

> 调研结论：在现有 IOTO Task Center 代码上实现"批量选中 + 批量编辑"**可行**，难度为**低 ~ 中**。
> 原因是所有单任务的写操作（改优先级 / 标记核心 / 删除 / 设置或移除上级任务）在文件层都已经有独立函数，
> 批量编辑本质上就是"循环调用这些单任务写函数 + 一次统一刷新"，没有需要从零写的核心难点。
> 真正要新增的只有三块：**选择状态**、**批量模式的渲染开关**、**批量操作执行层**。

---

## 一、现有代码里可直接复用的能力（调研依据）

| 能力 | 视图层（单任务） | 文件层（可直接批量循环） | 位置 |
| --- | --- | --- | --- |
| 改 / 清优先级 | `view.updateTaskPriority` / `clearTaskPriority` | `setTaskFilePriority(app, file, p)` / `clearTaskFilePriority` | `src/tasks-center/task-priority.ts:11` |
| 标记 / 取消核心 | `view.updateTaskStarred` / `clearTaskStarred` | `setTaskFileStarred(app, file)` / `clearTaskFileStarred` | `src/tasks-center/task-starred.ts:3` |
| 删除任务 | `view.confirmAndDeleteTask` | `trashTaskFile(app, file)` | `src/tasks-center/task-deletion.ts:3` |
| 设置上级任务（移动 / 设父子） | —— | `assignUpTaskToFile(app, file, parentTitle)` | `src/tasks-center/up-task-assignment.ts:26` |
| 移除上级任务 | —— | `removeUpTaskFromFile(app, file)` | `src/tasks-center/up-task-assignment.ts:48` |

关键观察：
- 文件层函数（`task-priority.ts` / `task-starred.ts` / `task-deletion.ts` / `up-task-assignment.ts`）**全部接收 `app + TFile`**，不依赖视图交互，天然适合批量循环。
- 视图层单任务函数（如 `updateTaskProperty`，`src/views/tasks-center/task-operations.ts:598`）每次都会单独 `refreshCurrentProjectTasks`，**不适合直接批量调用**（会刷新 N 次）。批量层应直接调用文件层函数，**最后只刷新一次**。
- 行渲染逻辑集中在 `src/views/tasks-center/task-row-renderer.ts`，每行是一个 `<button data-task-path="...">`，已有 `click` / `contextmenu` / `dragstart` 等事件（`task-row-renderer.ts:198`）。
- 命令注册模式已在 `main.ts:157` 的 `batch-create-tasks-from-template` 中示范：先 `getLeavesOfType` 找到视图实例，再调用视图方法。批量操作命令可直接照搬此模式。
- 视图已有一套"状态集合 + 渲染"的成熟范式：`collapsedTaskGroups` 用 `Set` 存储、`toggleSetMember` 切换、`render()` 重绘（见 `iotoTasksCenterView.ts:199`、`:997`）。选择状态可完全照搬。

## 二、总体设计

### 2.1 用户偏好对齐
任务描述里明确"**倾向于命令**进入批量编辑状态，不想让 UI 太复杂"。因此：

- **进入 / 退出批量模式 = 命令**（命令面板可触发，键盘可达）。
- 批量模式下，任务列表顶部出现一条**仅在批量模式可见**的轻量操作栏（选择计数 + 各批量动作按钮 + 退出）。非批量模式下完全不渲染，不增加常态 UI 负担。
- 每个批量动作**也注册成命令**，因此既可用顶部栏点，也可用命令面板调。

### 2.2 新增状态（放在视图实例上，仿照现有集合范式）
```ts
// iotoTasksCenterView.ts
public isBatchEditMode = false;
readonly selectedTaskPaths = new Set<string>();   // 与 collapsedTaskGroups 同风格

toggleBatchEditMode(): void {
    this.isBatchEditMode = !this.isBatchEditMode;
    if (!this.isBatchEditMode) this.selectedTaskPaths.clear();
    this.render();
}

toggleTaskSelected(taskPath: string): void {
    toggleSetMember(this.selectedTaskPaths, taskPath);
    this.render();   // 或只切换该行 class，见 2.3
}

getSelectedTasks(): TaskFileEntry[] {
    return this.tasks.filter((t) => this.selectedTaskPaths.has(t.path));
}
```

## 三、选择交互（两种方案，推荐 A）

### 方案 A（推荐）：批量模式下"整行点击 = 切换选中"，并提供复选框视觉
- 批量模式下，`rowEl` 的 `click` 不再打开文件，而是 `toggleTaskSelected`。
- 行首加一个复选框视觉（`◻ / ◻️`），命中 `is-selected` 时高亮，复用现有 `is-active` 等 class 的样式套路。
- 退出批量模式后，点击恢复为打开文件（现有行为不变）。
- **优点**：无嵌套交互元素、改动最小、心智模型清晰。
- **取舍**：批量模式期间不能直接打开任务查看；需要查看时退出批量模式即可（也可额外支持 Ctrl/Cmd+点击 在批量模式下仍打开，作为可选增强）。

### 方案 B：常驻复选框列
- 每行前永远有一个 `<input type=checkbox>`，无论是否在批量模式。
- 批量模式只控制"操作栏是否出现"。
- **取舍**：常态也会看到复选框，稍微增加视觉噪音；且 checkbox 嵌在 `<button>` 里属非法嵌套，需要把行从 `<button>` 改为 `<div role=button>`，对现有渲染改动更大。**不推荐**。

> 结论：选 **方案 A**。

### 4.3 批量操作执行层（新增文件）
新增 `src/views/tasks-center/batch-edit-operations.ts`，直接循环文件层函数，**统一刷新一次**：
```ts
import { Notice, TFile } from 'obsidian';
import type { IOTOTasksCenterView } from '../iotoTasksCenterView';
import type { TaskFileEntry } from '../../tasks-center/types';
import { setTaskFilePriority, clearTaskFilePriority, TaskPriorityValue } from '../../tasks-center/task-priority';
import { setTaskFileStarred, clearTaskFileStarred } from '../../tasks-center/task-starred';
import { trashTaskFile } from '../../tasks-center/task-deletion';
import { assignUpTaskToFile, removeUpTaskFromFile } from '../../tasks-center/up-task-assignment';
import { t } from '../../lang/helpter';

async function eachSelectedFile(
    view: IOTOTasksCenterView,
    action: (file: TFile) => Promise<void>,
): Promise<{ ok: number; fail: number }> {
    let ok = 0, fail = 0;
    for (const task of view.getSelectedTasks()) {
        const file = view.app.vault.getAbstractFileByPath(task.path);
        if (!(file instanceof TFile)) { fail++; continue; }
        try { await action(file); ok++; }
        catch { fail++; }
    }
    return { ok, fail };
}

export async function batchSetPriority(view: IOTOTasksCenterView, priority: TaskPriorityValue): Promise<void> {
    const r = await eachSelectedFile(view, (f) => setTaskFilePriority(view.app, f, priority));
    await view.refreshFromVaultChange();
    new Notice(t('notice.batchEdit.priorityDone', [String(r.ok)]));
}

export async function batchClearPriority(view: IOTOTasksCenterView): Promise<void> {
    const r = await eachSelectedFile(view, (f) => clearTaskFilePriority(view.app, f));
    await view.refreshFromVaultChange();
}

export async function batchSetStarred(view: IOTOTasksCenterView, starred: boolean): Promise<void> {
    const r = await eachSelectedFile(view, (f) => starred ? setTaskFileStarred(view.app, f) : clearTaskFileStarred(view.app, f));
    await view.refreshFromVaultChange();
}

export async function batchAssignUpTask(view: IOTOTasksCenterView, parentTitle: string): Promise<void> {
    const r = await eachSelectedFile(view, (f) => assignUpTaskToFile(view.app, f, parentTitle));
    await view.refreshFromVaultChange();
}

export async function batchRemoveUpTask(view: IOTOTasksCenterView): Promise<void> {
    const r = await eachSelectedFile(view, (f) => removeUpTaskFromFile(view.app, f));
    await view.refreshFromVaultChange();
}

export async function batchDeleteTasks(view: IOTOTasksCenterView, confirmed: boolean): Promise<void> {
    if (!confirmed) return;
    const r = await eachSelectedFile(view, (f) => trashTaskFile(view.app, f));
    await view.refreshFromVaultChange();
    new Notice(t('notice.batchEdit.deleted', [String(r.ok)]));
}
```
> 删除建议先弹一次确认（复用 `ui/confirmModal.ts` 的 `ConfirmModal`），再循环 `trashTaskFile`，与现有 `confirmAndDeleteTask`（`task-operations.ts:674`）行为一致。

## 六、风险与注意点

1. **父子关系边界**：`trashTaskFile` 只删单个文件。批量删除父任务时，其子任务文件仍保留，且其 `UpTask` 仍指向被删父任务的 wikilink（悬空引用，不崩溃，但会显示失效链接）。
   - 缓解：批量删除时**同时删除被选中任务的直接子任务**，或删除前向用户提示"将一并移除 N 个子任务"。这是唯一需要稍加判断的地方。
2. **重刷频率**：务必在循环结束后只 `refreshFromVaultChange()` 一次，不要每个任务刷一次（现有 `updateTaskProperty` 每次都刷，不适合批量）。
3. **与拖拽 / 悬停预览共存**：批量模式下的 `click` 分支要 `event.preventDefault()` 且不触发 hover-preview；现有 `mouseover` 仍可能触发预览，必要时在批量模式也跳过 `triggerTaskHoverPreview`。
4. **选择集合的清理时机**：切换项目、退出批量模式、删除完成后都应清空 `selectedTaskPaths`，避免脏状态。
5. **"移动 / 设或移除子任务"的歧义**：理解为"设置 / 移除任务的 `UpTask`（上级任务）"，对应 `assignUpTaskToFile` / `removeUpTaskFromFile`。若"移动"另指"在同层级内重新排序"，现有拖拽已支持单任务移动，批量重排建议后续单独评估，不在本期范围。

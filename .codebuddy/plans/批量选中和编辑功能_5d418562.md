## 产品概述

为 IOTO Task Center 任务列表增加批量选中与批量编辑能力，使用户能够一次性对多个任务执行删除、设置/清除优先级、标记/取消核心任务、设置/移除上级任务等操作。

## 核心功能

- 通过命令进入/退出批量编辑模式，非批量模式下 UI 零侵入
- 批量模式下任务行首显示复选框视觉，整行点击切换选中状态，已选行高亮
- 批量模式顶部出现轻量操作栏：显示已选计数、全选、退出，以及各批量动作按钮（删除、设优先级、清优先级、标记核心、取消核心、设上级、移除上级）
- 每个批量动作同时注册为命令，可通过命令面板触发
- 批量删除前弹确认弹窗，操作完成后统一刷新一次（非逐个刷新）
- 切换项目、退出批量模式、操作完成后自动清空选择集合，避免脏状态
- 批量模式下跳过 hover 预览，避免干扰选中交互

## 技术栈

- 语言: TypeScript (strict mode)
- 框架: Obsidian Plugin API
- 构建工具: esbuild (已有配置)
- i18n: 自有 `t()` 翻译函数 + 三语 locale 文件 (en / zh-cn / zh-tw)
- 样式: styles.css (原生 CSS，复用现有 BEM 风格 class 体系)

## 实现方案

### 策略概述

批量编辑本质上 = "选择状态管理 + 批量模式渲染开关 + 循环调用已有文件层写函数 + 最后统一刷新一次"。所有单任务文件层写函数（`setTaskFilePriority` / `clearTaskFilePriority` / `setTaskFileStarred` / `clearTaskFileStarred` / `trashTaskFile` / `assignUpTaskToFile` / `removeUpTaskFromFile`）已存在且签名统一为 `(app, TFile, ...)`，天然适合循环调用。不新建模式，完全复用视图已有的 `Set + toggleSetMember + render()` 状态范式（参照 `collapsedTaskGroups`）。

### 关键技术决策

1. **交互方案选 A（行点击切换选中）**: 批量模式下行 `click` 不打开文件而切换选中，行首用 `span + setIcon('check-square'/'square')` 做复选框视觉（不用 `<input>`，规避 button 内嵌 input 的非法 DOM 结构）。退出批量模式恢复原有打开行为。理由：改动最小、无嵌套问题、心智模型清晰。
2. **批量操作不直接调用视图层单任务函数**: 视图层 `updateTaskProperty`（`task-operations.ts:598`）每次单独 `refreshCurrentProjectTasks`，批量调用会刷新 N 次。新建执行层直接循环文件层函数，循环结束后只调一次 `view.refreshFromVaultChange()`。
3. **进入/退出批量模式 = 命令**: 符合用户"倾向命令"偏好，键盘可达，不增加常态 UI 负担。
4. **批量删除先弹 ConfirmModal**: 复用 `src/ui/confirmModal.ts` 的 `ConfirmModal.openAndConfirm()`，与单任务 `confirmAndDeleteTask`（`task-operations.ts:674`）行为一致。
5. **批量设优先级/设上级任务复用 Menu 菜单交互**: 参照 `menus.ts:291` 的 `showTaskPriorityMenu` 用 `Menu()` + `TASK_PRIORITY_VALUES` 循环构造菜单项的模式。

### 性能与可靠性

- **重刷频率**: 批量循环内不刷新，循环结束后只调 `refreshFromVaultChange()` 一次。时间复杂度 O(N) 文件读写 + O(1) 刷新，N 为选中数。
- **选择集合清理时机**: `selectProject`（`data-loader.ts:108`，已有 `collapsedSubtaskParents.clear()` 处）、`toggleBatchEditMode` 退出时、删除完成后均清空 `selectedTaskPaths`。
- **批量模式跳过 hover 预览**: `task-row-renderer.ts:203` 的 `mouseover` 处理器在 `isBatchEditMode` 时提前 return，避免干扰。
- **父子关系边界**: 批量删除父任务时其子任务 `UpTask` 会产生悬空引用。删除前在确认弹窗中提示用户该行为，不自动级联删除子任务（保持与单任务删除一致）。

## 实现注意事项

- `setIcon` 已在 `task-row-renderer.ts:7` 导入，复选框视觉直接用，无需额外导入
- `toggleSetMember` 已在 `helpers.ts:64` 存在且已被视图导入（`iotoTasksCenterView.ts:142`），直接复用
- `TaskFileEntry.path` 是唯一键（`types.ts:48`），用作 `selectedTaskPaths` 的 Set 成员
- `getVisibleTasks()`（`iotoTasksCenterView.ts:976`）返回当前可见任务数组，`selectAllVisibleTasks` 基于此填充
- 批量优先级菜单复用 `TASK_PRIORITY_VALUES`（`task-priority.ts:3`），无需新增常量
- 批量设上级任务需要用户输入父任务标题，复用 `taskNameModal.ts` 的输入弹窗模式或简单用 `Modal` + `TextComponent`
- 批量删除确认弹窗描述中应包含选中数量，参照 `modal.batchDelete.desc` 格式
- `Notice` 成功提示应包含操作计数，失败时显示失败数和原因
- 保持 `isDesktopOnly: false` 兼容移动端，不使用 Electron/Node API
